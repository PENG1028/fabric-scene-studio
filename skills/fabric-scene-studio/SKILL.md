# 面料场景工作室

把用户实拍面料变成可穿着、有设计感的服装或合理家居应用。分别评估指定面料是否准确、设计是否成立、人物与摄影是否自然；漂亮的照片不代表面料验收通过。

## 选择入口

- 用户在 ComfyUI 调图：优先保留已有画布与开关，使用单场景按钮或裁剪后的单分支请求。先读 [本机位置与节点](references/local-workflow.md)。不要为普通调图重写稳定节点。
- 用户希望带走、换机器或脱离界面运行：使用本 Skill 的 `scripts/fabric_scene.py` 和配方文件，不需要 ComfyUI、Electron、torch 或指令模型。读 [独立运行与配方](references/portable.md)。
- 用户主要问审美或还原问题：先读 [视觉调试](references/visual-review.md)，检查真实输入、完整提示词和生成设置，再决定要改什么。

Skill 本身不提供生图额度。当前项目使用用户指定的 API Key / Images API 兼容地址；不要自行切回 Codex 套餐、换模型或中转站。

## 输入与复用

1. 看用户本组完整平面图及补充实拍，明确哪一张决定总体色彩与重复分布，哪些解释透光、厚薄和弯折。逐张独立说明；保留完整画幅。
2. 同一组图片按名字和实际内容核实。`{stem}-3.JPG` 等是本批次方便换号的约定，别当作所有客户文件夹都遵循的规则。缺图先报告，不借其他组补齐。新组织不能盲套旧布说明。
3. 材料事实与服装设计分开。用照片中可见的纱束、孔隙、光泽、透光和褶皱描述材料；未知成分、克重、毫米尺度不猜。主布单层透明，就用独立不透配料解决遮蔽，不在图里把主布加厚。
4. 有风格图时，明确是否真的上传给模型，别把“看过参考图并写了文字”说成“已传入参考图”。风格图只控制人物状态、设计语言和摄影；实拍决定面料。传入风格图后要修改“所有附图都是面料”的旧规则，并逐张标出角色。
5. 先复用材料描述与必要穿着条件。款式、轮廓、衣长、袖型、配料关系应按用户目标变化；不要把同一模特发型、固定冷淡神态、长马甲、黑裤、灰墙组合固化成万能风格。

该用户目前偏好成年亚洲模特、自然但精致、有创意仍能穿的设计师品牌风格，全身图完整保留双鞋，鞋包头包跟。配料可由模型提出，但要指出它不是用户提供的另一组布。后续用户的新偏好优先。

## 生成与评估

- 遵循本次和先前仍有效的用户授权；已授权的一轮不重复索要同意。写 Skill、导出、改文案或解释差距不自动变成一轮付费生图授权。
- 按用户的质量与成本目标选择档位。`low` 用来选款，不能拿低档预览断言最终画质上限。需要比较时固定布料、款式、构图，先只变质量；提高质量不保证织物组织准确。
- 一次只运行选中的一个场景、`n=1`，先检查它再继续下一次。不要为了方便执行全部开启的工作流。
- 独立入口先 `prepare`。缓存命中可 `run --offline`；需要实际生成且已有授权时才使用 `run --allow-paid`。参数开关是防误操作，不代替用户授权，也不要求重复确认。
- 服务端超时、断连或返回图片读取失败可能已经计费，查请求日志后处理；不要自动重试、切模型或切端点。
- 原始 usage 和请求编号落日志；官方金额按公开单价估算，中转价格未知就写未知。无 usage 不是零。不要给未经测量的单张美元硬上限。
- 把每张输出映射回材料编号、照片清单、配料、最终提示词、质量、成本和待改问题。保真与审美分别下结论，不编百分比。
- 缓存只复用已有图片。`variation` 是本地缓存版本，不是 seed。每个方向只生成一张不能证明重生成稳定性。

## 交付

展示所生成或复核的单张图片，说明用的哪块布、哪部分是配料、好在哪里及具体误差，并链接完整提示词/配方和用量记录。用户没要拼版，就不生成拼版。维护现有 v7 时原位保存并保留旧模板；便携配方与画布不是实时双向同步，清楚说明本次改动在哪一边。


透明度控制：可使用FabricTransparencyControls节点或配方material_controls。先标定五列对照图，再按档位裁切；默认text仅发送文字，image附选中一列。示意图不能提供材质/颜色/款式，不裁切真实面料替代完整平面图。换图重新标定，透明度档位不是测量。
